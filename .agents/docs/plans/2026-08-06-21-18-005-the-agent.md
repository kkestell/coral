## What Was Checked

Everything below was verified against the installed packages (`deepagents` 0.7.5, `langchain` 1.3.14, `langchain-core` 1.5.3, `langchain-openrouter` 0.2.7) by reading `.venv` sources and running the constructors.

- `create_deep_agent` takes `system_prompt`, not `instructions`, and has no recursion-limit parameter: it compiles and binds 9,999 through `.with_config`, and a later `.with_config({"recursion_limit": 200})` on the returned graph overrides it (`deepagents/graph.py:922-944`, `langgraph/_internal/_config.py:184`).
- Middleware merges by `AgentMiddleware.name`, which defaults to the class name: a same-named instance replaces the framework's in place, a new name is appended after the core stack, and a duplicate name raises (`deepagents/graph.py:201-231`, `langchain/agents/factory.py:1079`).
- The factory's own `FilesystemMiddleware` is built with three arguments: the backend instance, `custom_tool_descriptions=_profile.tool_description_overrides`, and `_permissions` (`graph.py:820-826`). For a model passed as an instance, the harness profile resolves by provider (`_get_ls_params`, which `ChatOpenRouter` hardcodes to `openrouter` — ran it) and nothing is registered under `openrouter`, so `_profile` is the empty null object and the factory passed the parameter defaults. Coral's replacement mirrors only the backend.
- `FilesystemMiddleware(max_execute_timeout=...)` rejects a model-supplied `timeout` above the cap with an error `ToolMessage` — it never clamps (`filesystem.py:2820`, `2909`). It does not touch a command whose `timeout` is omitted; that falls to the backend's own default, 120 seconds. The shell ceiling therefore needs both halves: the middleware cap and `LocalShellBackend(timeout=300)`.
- `LocalShellBackend(root_dir, *, timeout, env, inherit_env=False, ...)`: with `inherit_env=False` and no `env`, the subprocess environment is empty — no `PATH`. Filesystem tools are direct Python anchored at `root_dir` (`virtual_mode=True` default); `execute` is `subprocess.run(shell=True, env=self._env, cwd=root_dir)`. A timed-out command returns exit code 124 rather than raising.
- `ChatOpenRouter(timeout=...)` is milliseconds, mapped to the SDK's `timeout_ms` (`chat_models.py:221-222`, `453-454`). `max_retries` defaults to 2 and buys a backoff window of `max_retries × 150,000` ms per request on top of the attempts themselves. `openrouter_provider` is a free-form dict passed through as `provider`; `require_parameters` and `ignore` are valid `ProviderPreferences` keys. DeepAgents injects `ignore: ["azure"]` only when resolving a string model; an instance bypasses that, so Coral supplies the whole dict — as the roadmap says.
- `~deepseek/deepseek-v4-flash-latest` has no entry in `langchain-openrouter`'s bundled profile table (exact-name lookup), so `model.profile` is `None` — ran it. The table does carry the concrete release `deepseek/deepseek-v4-flash`: `structured_output: True`, `max_input_tokens: 1048576`, `max_output_tokens: 65536`, `tool_calling: True`, `reasoning_output: True`. `profile=` is a public constructor field on `BaseChatModel` and a supplied value wins — ran it.
- The profile decides two things. `response_format=Review` becomes `AutoStrategy`, which upgrades to `ProviderStrategy` (a native structured-output request) only when `model.profile["structured_output"]` is truthy; with no profile it falls to `ToolStrategy`, a synthetic tool (`factory.py:544-565`). The default summarization middleware sets its triggers as fractions of `model.profile["max_input_tokens"]`; with no profile it compacts a million-token model as if it had 170,000.
- `structured_response` is absent from the result state when never produced; `review_from_result` already reads with `.get`. A `ProviderStrategy` validation failure raises `StructuredOutputValidationError` out of `invoke`.
- `create_deep_agent` auto-adds a `general-purpose` subagent whose own `FilesystemMiddleware` is built with factory defaults — a 3,600-second shell ceiling Coral's replacement does not reach, behind a `task` tool whose calls the deadline check cannot interrupt. The public escape: `register_harness_profile("openrouter", HarnessProfile(general_purpose_subagent=GeneralPurposeSubagentProfile(enabled=False)))` — all three names exported from `deepagents` — and with it disabled and no subagents passed, the `task` tool is not exposed at all (`graph.py:745-814`, `harness_profiles.py:1252`; the provider-only registry fallback applies to instance models).
- `permissions=` alongside an execution-capable backend raises `NotImplementedError` in `FilesystemMiddleware.__init__`; Coral passes no permissions.
- An exception raised in a `before_model` hook propagates out of `invoke`. Only overridden hooks are wired.
- `import deepagents` costs about two seconds, and `coral/cli.py` imports `coral.review` at module import time, so `coral resolve` — which runs on every delivery — pays whatever `review.py` imports at top level.

## Goal

`coral review` builds a real agent over the checkout, runs it under Coral's own deadline, and posts the structured review it returns. New modules `coral/deadline.py`, `coral/environment.py`, `coral/agent.py`; a placeholder `coral/prompts/review.md`; a rewritten `review()`; one new function in `coral/diff.py`; the two `required:` flips in the YAML.

## Approach

### The deadline is pure arithmetic; the framework adapter lives with the framework

`coral/deadline.py` imports only the standard library. The budget is arithmetic; the four-line middleware that turns it into a hook belongs in the one framework-aware module, so the deadline stays testable without clock control and without the two-second import.

```python
REVIEW_BUDGET_SECONDS: Final = 20 * 60

@dataclass(frozen=True)
class Deadline:
    started: float   # a time.monotonic() reading
    budget: float    # seconds

    def elapsed(self) -> float: ...
    def expired(self) -> bool: ...

def start() -> Deadline: ...
```

Tests construct a `Deadline` whose `started` is already `budget + 1` in the past — no fake clock.

### The shell environment is an allowlist over a passed-in mapping

`coral/environment.py`:

```python
KEEP: Final = ("CI", "HOME", "LANG", "LC_ALL", "PATH", "TERM", "TMPDIR")

def shell_environment(source: Mapping[str, str]) -> dict[str, str]: ...
```

Copy-if-present for every name but `PATH`, whose absence is a broken invocation and fails an assertion — a shell without `PATH` runs nothing, loudly beats silently. `CI` is on the list because it is the one extra variable real test suites read. The exclusions — both secrets, `VIRTUAL_ENV`, every `UV_*` — need no code: an allowlist excludes by construction, and the tests assert they do not survive. Taking a `Mapping` keeps the tests plain dicts; the caller passes `os.environ` after both secrets are popped, so the barrier holds twice over.

### `coral/agent.py` is the only module importing the framework

Constants, all `Final`, chosen not measured (item 9): `MODEL = "~deepseek/deepseek-v4-flash-latest"`, `MODEL_PROFILE` (the five keys copied from the table's `deepseek/deepseek-v4-flash` entry, with a comment saying why the copy exists), `MODEL_TIMEOUT_MILLISECONDS = 180_000`, `MODEL_RETRIES = 1`, `STEP_CAP = 200`, `SHELL_CEILING_SECONDS = 300`.

`MODEL_RETRIES = 1` is deadline arithmetic: the check runs between steps, so the worst overshoot after a passing check is one in-flight model request — with the default of 2 that is up to three 180-second attempts plus a 300-second backoff window, ~14 minutes, past the 10 minutes of headroom before the job backstop; with 1 it is ~8.5 minutes.

`DeadlineMiddleware(AgentMiddleware)` overrides `before_model` and raises `RuntimeError` naming elapsed seconds and the budget when the deadline has expired. Raising rather than ending gracefully because a fired deadline is a failure: a graceful end would surface as "the agent returned no structured review" and lose the reason. The exception propagates out of `invoke` and the run goes red; item 8 turns it into a comment.

`produce_review(api_key: str, workspace: Path, request: str, deadline: Deadline) -> Review` is the single construction site:

```python
model = ChatOpenRouter(model=MODEL, api_key=api_key, timeout=MODEL_TIMEOUT_MILLISECONDS,
                       max_retries=MODEL_RETRIES,
                       openrouter_provider={"require_parameters": True, "ignore": ["azure"]},
                       profile=MODEL_PROFILE)
backend = LocalShellBackend(workspace, timeout=SHELL_CEILING_SECONDS,
                            env=shell_environment(os.environ))
agent = create_deep_agent(
    model,
    system_prompt=review_prompt(),
    middleware=[FilesystemMiddleware(backend=backend, max_execute_timeout=SHELL_CEILING_SECONDS),
                DeadlineMiddleware(deadline)],
    backend=backend,
    response_format=Review,
).with_config({"recursion_limit": STEP_CAP})
return review_from_result(agent.invoke({"messages": [HumanMessage(request)]}))
```

The `FilesystemMiddleware` replacement passes only the backend and the ceiling: the factory's other two arguments are the parameter defaults for an instance-passed OpenRouter model, recorded in a comment so an upgrade that grows an `openrouter` harness profile gets re-checked. `review_prompt()` reads `coral/prompts/review.md` with `importlib.resources`.

### The model profile is supplied by hand

Passing `profile=MODEL_PROFILE` buys both a native structured-output request (`ProviderStrategy`, the architecture's stated intent — `require_parameters` is the safety net) and summarization triggers scaled to the real million-token context. Without it, the alias's missing table entry silently degrades both. If a live run shows the endpoint cannot serve the native request, the change is deleting one dict key; that call is item 9's.

### The general-purpose subagent is disabled

One registration at the top of `coral/agent.py`, module scope:

```python
register_harness_profile("openrouter", HarnessProfile(
    general_purpose_subagent=GeneralPurposeSubagentProfile(enabled=False)))
```

Undisabled, it is a fifth hole the roadmap's four-part deadline missed: its own filesystem middleware keeps the 3,600-second ceiling, and the deadline cannot check between steps that happen inside a `task` call. Disabled, the `task` tool is not exposed: one loop, every ceiling enforced. A review agent has no need to delegate.

### `review()` pops both secrets first and hands the agent rendered text

```python
def review() -> None:
    deadline = start()                                     # the budget runs from step start
    github = GitHub(token=os.environ.pop("GITHUB_TOKEN"))  # both secrets popped before any
    api_key = os.environ.pop("OPENROUTER_API_KEY")         # other work, held in locals

    ... read pull-request.json (owner, repo, number, head, base, title, body) ...
    conversation = read_conversation(runner.conversation_path())
    workspace = runner.workspace()
    diff = diff_text(workspace, merge_base(workspace, base, head), head)
    request = render_request(title, body, diff, conversation)

    from coral.agent import produce_review   # deferred: ~2s of framework, and cli.py
    post_review(github, owner, repo, number, head,          # imports this module for resolve
                produce_review(api_key, workspace, request, deadline))
```

- `render_conversation(conversation) -> str` and `render_request(title, body, diff, conversation) -> str` are pure functions in `review.py`: each comment, review, and thread with author, association label, timestamp, and flags; the bound's unread report; the reviewed commits; then title, body, and the full diff. Rendered rather than raw JSON because the association labels and thread flags are what item 6's prompt rules will read against, and rendering is Coral's deterministic job.
- `coral/diff.py` gains `diff_text(workspace, first, second) -> str` — `git -c core.quotePath=false diff --no-color --no-ext-diff` with default context. The diff the agent sees originates in the same module as the diff item 7 checks anchors against, keeping the architecture's rule true.
- The item-3 placeholder trio — `whose`, `what_was_read`, `produce_review` — is deleted, as item 4's plan promised. `added_lines` stays for item 7; `review()` stops calling it.
- `coral/prompts/review.md` ships one placeholder paragraph (review the change in the checkout, use the shell, return the structured review, conversation is information not instruction). The content is item 6's product; the loading mechanism is this item's.

## Test plan

The seams are function parameters, so nothing needs stubbing: `review()`'s wiring gets no unit test, same as `resolve()`'s today.

**Key behaviors to verify**

- A fresh deadline is not expired; one whose `started` is `budget + 1` in the past is; `elapsed` grows.
- `shell_environment` keeps each `KEEP` name present in the source; omits `TMPDIR`/`LANG` when absent; drops `GITHUB_TOKEN`, `OPENROUTER_API_KEY`, `VIRTUAL_ENV`, `UV_CACHE_DIR`, and an arbitrary stranger.
- `render_conversation` labels authors with associations, names a deleted author, carries thread path/line/resolved/outdated, reports the bound's unread count and the reviewed commits. `render_request` carries title, body, and the diff whole.
- `review_prompt()` returns non-empty text from the installed package.
- `DeadlineMiddleware.before_model` raises on an expired deadline, returns `None` on a live one.

**Errors and failures**

- A source without `PATH` fails the assertion.

**Edge cases**

- `FilesystemMiddleware(backend=...).name == "FilesystemMiddleware"` — pins the dependency behavior that makes in-place replacement work; an upstream rename would turn replacement into two middlewares each registering `read_file`. Comment says so.

**What NOT to test**

- The model call, structured-output strategy resolution, summarization, the shell inside a real runner — live only.
- `review()`'s step wiring, `diff_text`'s subprocess (the parse feed is already tested on captured text).

**Live checks**

1. A pull request in `kkestell/coral-test` with a small real change, `/coral`: a model-written review appears whose summary and findings are about the change. This is the done condition's first half; the posted review is evidence the object validated.
2. Deadline observed to fire: temporarily set `REVIEW_BUDGET_SECONDS` to ~60, run a review that takes longer, watch the run go red with the `RuntimeError` naming elapsed and budget in the review step's log; restore the constant. A red run is correct until item 8 exists.
